# dsh-ob-agent 0.2.0

本版适配 DSH 0.2.1-rc.2，处理插件管理、团队兼容和界面问题。已有模型服务、接口协议、凭据及角色的显式模型选择保持原值。

## 普通子代理与关闭约束

普通模式继续按会话保存总开关和勾选。关闭后隐藏继承面的代理工具，由执行守卫拒绝残留自有层工具；每轮动态提示明确禁止委派、续话、中止、工作流和自助管理，不允许沿用历史对话或记忆中的工具名。开启但没有可用条目时，同样明确禁止调用未启用能力。

正在执行的请求不会因为提示词更新自动撤回；设置影响后续请求与后续工具执行。已有子任务不会被静默取消；受管子代理仍保留创建时的安全策略。

## 智能体团队模式

在聊天框展开面板或插件设置里打开「智能体团队模式」，等待设置保存完成，然后在 DSH 插件页启用官方「智能体团队」。此开关表示本插件交还管理权，不会自动安装或启用官方团队包。返回普通模式时，先关闭官方团队，再关闭本插件的团队模式。

团队模式下本插件释放普通角色工具、续话/列表/工作流等重挂、闸门隐藏、执行守卫及能力提示，不改写官方团队的工具、消息参数、任务板或成员权限。角色和会话勾选保留，退出后恢复。官方 `agentTeams` 服务已存在时也自动避让，防止误关本插件模式开关后抢回同名工具。

截图中的 `tool "send_message" is already registered in this scope` 来自官方团队和本插件在同一个 Agent 自有作用域注册同名工具。官方团队开关只能禁用官方普通子代理入口，无法卸载本插件自行重挂的工具，因此必须先释放本插件接管。若旧版本已启用失败，升级后重启原 DSH、刷新页面，再按上述顺序启用。

自动检测服务可覆盖冷启动及团队已启用后的新会话；直接在旧实例上热启用官方团队存在宿主装配时序竞争，因此仍应先打开本插件的团队模式。插件卸载时会等待回收自身持有的 Agent 工具装配，避免留下同名注册。

历史 `obagent-` 子代理的不可变身份/只读策略仍需执行，这是原会话恢复所需的权限边界；它们不会被转换为官方队员。官方团队新建成员不使用此命名空间，不受这套策略校验影响。

## 配置与继承修复

- `agent_update` 只要求 `id`；省略字段保持原值，不再因只改描述而丢失固定模型及思考档位，也不改变条目来源。
- 显式路由必须成对提供，非法枚举或字段类型会收到中文拒绝；恢复继承使用 `inheritModel: true`，不能靠省略字段清空。
- 创建时首次立即启用保留原有默认勾选，不丢失其他角色。
- 能力清单展示权限、上下文、模型与思考档位；关闭总开关不会把已勾选误报为已启用。
- 不再写死 `maxDepth: 3`，委派深度由 DSH 公开工具实现读取宿主设置。没有显式模型时由 DSH 继承；新安装的默认审查角色也不指定厂商路由。已有用户角色不被清空。
- 策略目录支持显式 `dshHome`，优先级为 `DSH_OB_AGENT_POLICY_DIR`、显式根目录、`DSH_HOME`、`~/.dsh`。修改根目录前应迁移相应策略文件；插件不自动搬迁或删除快照。
- 角色身份覆盖保留宿主的后缀提示，避免额外空段遮蔽部署约束。

权限仍由用户的「完全权限 / 只读」选择决定。只读使用文件工具白名单，不加入可执行任意命令的 shell。完全权限加审查身份提示并不等于强制只读，本版不会擅自收紧已保存角色。

创建失败可能留下策略文件；不自动 TTL 清理，以免误删冷恢复所需快照。备份会话时同时备份策略目录。

## 界面与升级

聊天框面板使用明确的展开/收起图标：收起时向上，展开时向下，不再叠加旋转样式反转方向。团队模式下普通管理项不可操作，但可以切回模式。

运行 `npm run check` 完成类型、测试和构建，再使用原宿主的插件安装命令更新本地依赖：

```powershell
dsh plugin --profile web add file:C:/path/to/dsh-OB-agent
```

更新后重启原 DSH 进程，并刷新原 GUI。源码构建不能保证运行中的后端自动更新，也不要另起替代 Web 服务器。升级前备份 profile 配置、依赖清单和锁文件。

# dsh-ob-agent 模型使用手册

> 这份文档是写给**模型**看的：它描述你在本部署里能用哪些 Agent 能力、工具的确切契约、
> 以及创建 Agent 时的写法规范。用户侧的说明见 `USAGE.md`。

## 1. 这个插件做了什么

本部署把 DSH 里**全部 agent 类工具**（委派、子代理续话、工作流、Ralph、以及自助管理）
收口到插件 `dsh-ob-agent` 统一管理。对你的直接影响有两条：

1. **总开关**：聊天框「子代理」条上的开关由用户控制。**关闭时你完全不能使用任何
   agent 类工具**——这些名字不会出现在你的工具清单里，即使你凭记忆直接调用，也会收到
   明确的拒绝信息。这不是故障，是用户的选择：请正常完成当前任务，需要委派时用一句话
   说明「需要用户打开子代理总开关」。
2. **按条目勾选**：开关打开后，只有被勾选的条目对应的工具才对你可见。你的工具清单
   与本部署的系统提示里「本会话已启用以下 Agent 能力」一段完全一致，**以工具清单为准，
   不要调用清单里没有的工具名**。

系统提示里每个条目都带三件事：工具名、模式/权限/上下文，以及**何时调用**
（`whenPrompt`）。它由用户或你自己撰写，是本部署对调用时机的权威说明。

## 2. 你能用的工具

| 工具 | 来源 | 契约 |
| --- | --- | --- |
| `subagent_<id>` | 条目 `id` + 一次性模式 | 参数 `description`（3-5 词短标题）、`prompt`（自包含任务说明）、可选 `run_in_background`。默认等待结果并返回内容；`run_in_background: true` 返回 job id，用 `job_output` 收集、`job_kill` 停止。 |
| `subagent_<id>_session` | 条目 `id` + 可继续对话模式 | 同上，但默认后台运行并返回**持久子代理 id**；之后用 `send_message` 续话、`interrupt_agent` 中止。 |
| `send_message` / `interrupt_agent` | 原生控制工具 | 需要「子代理续话与中止」条目被勾选（勾选可继续对话的子代理时通常会自动放行）。 |
| `list_agents` | 原生清单工具（本插件补了能力清单） | 查看当前会话有哪些子代理。结果分两段：**已启用的子代理工具**（能力清单，含工具名/模式/权限/模型）与**子代理实例**（仅「可继续对话」的实例会保留，含 id 与状态）。实例为空**不等于**没有子代理可用——一次性子代理跑完即结束、新会话更是没有任何实例；回答「有几个子代理」时必须看能力清单。 |
| `workflow` | DSH 工作流编排 | 脚本化扇出/分阶段；只在需要大量独立子任务时使用。 |
| `ralph` | DSH 深度迭代 | 只有用户明确要求「Ralph / 无人值守多轮推进」时才用。 |
| `agent_create` / `agent_update` / `agent_list` | 本插件 | 见第 3、4 节。 |

**并行**：相互独立的 agent 任务应在**同一条助手回复里同时发起调用**，不要串行等待。
需要某个子代理的结果才能决定下一步时，才用默认的前台等待。

**子代理看不到你的对话**：它只能看到你在 `prompt` 里写的内容（`fork` 后端例外，它继承
本会话已完成轮次）。任务说明必须自包含。

## 3. 什么时候该自建 Agent

先用 `agent_list` 查重，再决定：

**值得创建**（会反复出现、值得固化成固定角色）：

- 同类委派你已经做过至少两次，且每次都要重复交代同样的身份、边界与产出格式；
- 任务需要**固定的权限**（例如只读审查，绝不允许改代码）或**固定的模型**（例如审计必须
  用某个强模型）；
- 任务一旦跑起来就不需要你介入，且产出格式固定（报告、清单、结构化结果）。

**不要创建**：

- 一次性小任务——直接自己做，或用已有的通用子代理；
- 只是为了少写几句 prompt 的临时委派；
- 需要你频繁看中间结果再决定下一步的任务（那适合可继续对话的既有子代理，而不是新建角色）。

**创建后不会立刻可用**：新工具在**下一轮请求**才进入你的工具清单。不要在同一轮里调用
刚创建的工具；先向用户确认，或在下一轮再用。

## 4. 字段与写法规范

### 4.1 字段表

| 字段 | 必填 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | 是 | 2-24 位，小写字母开头，仅 `a-z0-9_`，全局唯一 | 派生工具名 `subagent_<id>` / `subagent_<id>_session`，创建后不要改 |
| `name` | 是 | ≤ 60 字符 | 界面显示名，出现在系统提示的启用清单里 |
| `whenPrompt` | 是 | ≤ 4000 字符 | ① 给**你**看的「何时调用」，进入每轮请求的系统提示 |
| `identityPrompt` | 是 | ≤ 4000 字符 | ② 给**子代理**看的身份提示词（persona），子代理看不到父会话，必须自包含 |
| `description` | 否 | ≤ 300 字符 | 界面展示用 |
| `modes` | 否 | `one-shot` / `continuable` 的子集，默认 `one-shot` | 两者都给会生成两个工具，由你选择调用哪一个 |
| `provider` | 否 | `spawn`（默认，全新上下文）/ `fork`（继承本会话已完成轮次） | 无关任务用 `spawn`；需要延续讨论才用 `fork` |
| `permission` | 否 | `full`（默认）/ `readonly` | `readonly` 只给文件读取类工具，**不能运行命令**；实际生效白名单是它与该子代理真实可见工具的交集，交集为空则该条目不可用 |
| `readOnlyAllow` | 否 | 工具名数组 | 覆盖全局只读白名单；只在 `permission: readonly` 时生效 |
| `modelProvider` + `model` | 否 | 必须**成对**给出；省略即继承主会话模型 | 钉死子代理使用的模型路由 |
| `defaultEnabled` | 否 | 默认 `false` | 新会话是否默认勾选（对当前会话无影响） |
| `enableNow` | 否 | 默认 `true` | 是否在**当前会话**立即启用；总开关未打开时只会创建条目 |

**提示词变量**：`whenPrompt` / `identityPrompt` 里可以写 `{{cwd}}`、`{{model}}` 等
**当前预设确实注册过的变量**（默认允许列表见系统提示或设置页）。两条硬约束：

1. 形式必须**严格**是 `{{小写名字}}`：不允许空格（`{{ cwd }}`）、不允许大写（`{{Cwd}}`）、
   不允许其它字符（`{{cwd-x}}`）。运行时的插值器只认这一种写法，其余一律抛错并**打断整个
   请求**，因此这类写法在写入时就会被拒绝。
2. 名字必须是当前会话装配里真实注册过的变量。不确定就不要写变量——写错的表现是整个请求
   失败，而不是这一句话失效。

### 4.2 `whenPrompt` 怎么写

它是你未来的决策依据，必须包含**正例与反例**：

```
用户明确要求审查时立即调用；否则每次实际修改文件后都立即调用（包括代码、配置和文档）。
一次工具调用同时修改多个文件时只审查一次；后续独立的文件修改仍需再次触发，不要推迟到任务结束。
纯问答和只读探索不调用；落实本次审查建议的低风险文字小修不复审。
审查建议须自行核实，误报或收益低于修改成本的建议可以不采纳；首次审查后的提示文案、注释、格式、测试断言等无行为变化小修不复审。
只有修复引入新的、测试无法覆盖的高风险行为时才针对新风险额外聚焦复审一次，同一问题最多一次，不要循环审查。
```

反例（不要这样写）：`用于代码审查。` —— 没有时机、没有边界，等于没写。

### 4.3 `identityPrompt` 怎么写

它是子代理的 persona。子代理看不到你，因此必须自包含：**身份 + 边界 + 流程 + 产出格式 + 纪律**。

```
你是独立代码审查员，只看改动和必要上下文，不修改代码。
优先检查有现实影响的正确性、安全、数据完整性和兼容性问题；只报告有证据且值得修复的风险，
注明文件:行号、触发条件、影响和最小修复方向。疑点标明待验证，不为凑数提出风格建议。
没有值得修复的问题就直接说明；避免无关的全仓扫描、重复测试和无收益的复审要求。
```

**边界必须写死**：能改什么、绝对不能改什么、失败时怎么办（如实报告而不是自作主张）。

## 5. 权限与可用性

- `permission: readonly` 的子代理**只能读文件**：没有 shell、没有写文件、没有 MCP 工具
  的写能力。它适合审查、分析、调研。
- 若只读白名单与它真实可见的工具没有交集，该条目会在装配期被**停用**（不会降级为完全
  权限），你会在系统提示里看不到它。
- 子代理**不能再委派**：任何层级都不提供 agent 类工具，因此不要设计「让子代理再开子代理」
  的方案，改成你自己分两轮做。

## 6. 常见错误与自愈

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| 工具返回「已被用户关闭」 | 用户在设置里关掉了自助管理 | 停止创建，改为用已有条目；如确有必要，请用户开启 |
| 「标识已被占用」 | `id` 与现有条目冲突 | 先 `agent_list`，换一个语义清晰的 `id` |
| 「提示词变量 {{x}} 不在允许列表内」/「无法解析的变量引用」 | 用了未注册变量，或写法不规范（空格/大写/其它字符） | 去掉变量，或改成严格的 `{{小写名字}}` 并让用户把它加进允许列表 |
| 「不是模型创建的条目」 | 默认作用域只允许改你自建的条目 | 内置/用户条目只能由用户在设置页修改；必要时新建一个自己的条目 |
| 「条目总数已达上限」 | 超过用户设定的上限 | 请用户删除不用的条目，或复用已有条目 |
| 新建的工具调用不了 | 新工具下一轮才可见 | 本轮不要调用；或总开关未打开、条目未勾选 |
| 工具被拒绝：「…被 dsh-ob-agent 拦截」 | 总开关关闭或条目未勾选 | 说明需要用户开启并勾选，不要反复重试同一个调用 |

## 7. 生效与审计

- 条目的创建/修改会**立即写入设置**（无需重启），但**工具可见性在下一轮请求生效**。
- 每次创建/修改都会留下一条中文审计日志（`dsh-ob-agent 审计：…`），用户可以在日志与会话
  里看到你改了什么。不要试图绕过它。
- 设置页会把你创建的条目标为「模型自建」，用户可随时停用或删除。

## 8. 不要做的事

- 不要创建身份含混、边界不清的「万能子代理」；
- 不要把用户的隐私、凭据、密钥写进提示词（提示词会进入系统提示与子代理 persona）；
- 不要为了让某个工具出现而反复创建条目（先查重、先问用户）；
- 不要在总开关关闭时反复尝试调用 agent 类工具。

# dsh-ob-agent 使用文档

统一管理 DSH 里**全部 agent 类工具**的插件：一个总开关、一张条目表、每会话勾选、
以及让模型自己创建 Agent 的能力。

- 面向模型的说明：`model-guide.md`（同一目录）
- 面向本插件的维护者：`../README.md`

---

## 1. 它解决什么问题

DSH 默认把委派与编排工具**直接暴露**给模型：`subagent`、`subagent_fork`、预设里的
具名子代理、`send_message`、`list_agents`、`workflow`、`ralph`。这带来两个问题：

1. 想「今天不想要子代理」时没有开关——只能改装配文件；
2. 每加一个专职子代理（例如代码审查）都要写一份 agent preset 文件，改提示词要动 YAML。

本插件把上述工具全部收进来，做成**可勾选的 Agent 条目**：

```
聊天框「子代理」总开关 ─┬─ 关闭 → 模型完全不能使用子代理（含 DSH 原生工具）
                       └─ 打开 → 只放行被勾选的条目，并把「何时调用」写进系统提示
设置页「子代理」      ──── 条目表 / 权限 / 模型 / 闸门名单 / 模型自助管理
```

## 2. 安装

```powershell
# 1) 加入 web profile（与其它 file: 本地插件一致）
#    C:\Users\17737\.dsh\profiles\web\package.json
#      dependencies:  "dsh-ob-agent": "file:C:/Users/17737/Code/other/DSH/plugins/dsh-OB-agent"
#      dsh.profile.bundles: 追加 "dsh-ob-agent"
# 2) 安装（在 profile 目录）
cd C:\Users\17737\.dsh\profiles\web
pnpm install
# 3) 重启 DSH 进程，然后浏览器 Ctrl+F5（客户端 bundle 需要重新加载）
```

> 插件作者未声明免重启生效，因此安装/更新后必须重启 DSH。

## 3. 界面

### 3.1 聊天框「子代理」面板（输入框上方）

面板结构与 DSH 官方的待办/队列面板一致：36px 首行 + 可展开列表，上圆角 12px、
0.5px 描边且无下边框，因此与下方输入卡片拼成一张连续表面。

| 元素 | 行为 |
| --- | --- |
| 首行图标 + **子代理** | 点击展开/收起条目列表（总开关关闭时不可展开）。 |
| 首行摘要 | 关闭时显示「已拦截全部 Agent 工具，模型无法调用子代理」；打开时显示已勾选数量。 |
| 首行右侧 **Switch** | 本会话总开关。打开时条目列表自动展开；关闭时保留勾选，再次打开即恢复。 |
| 条目行复选框 | 按「默认启用」规则预勾选，点行内任意处即切换并立即生效。 |
| 条目行右侧标签 | 模式（一次性 / 可继续对话）、只读权限标记、来源（DSH 原生 / 模型自建）。 |
| 条目名悬浮提示 | 该条目的「何时调用」提示词，方便核对模型看到的内容。 |
| **DSH 原生工具** 分组头 | DSH 自己实现的原生条目收在这一组里，**默认折叠**：平时只占一行，右侧显示该组已启用数量，点开才出现那 5 个复选框。 |

控件全部使用 DSH 自己的组件库（`@deepseek-ai/dsh-client-ui-primitives` 的
Switch / Button / Tag / Menu / Tooltip / DisclosureRow 与官方图标），配色、字号、
圆角、动效一律取设计令牌（`--dsw-alias-*` / `--dsw-font-*` / `--ds-*`），
因此自动跟随浅色/深色主题与「设置 → 外观 → 字号」偏好。

### 3.2 设置页「子代理」

- **全局**：新会话是否默认打开总开关、是否自动放行续话工具、只读工具白名单、
  提示词可用变量、模型文档注入方式（path / inline / off）。

> **提示词可用变量**：只有列在这里的变量才允许出现在提示词中，且写法必须**严格**为
> `{{小写名字}}`（`{{ cwd }}`、`{{Cwd}}`、`{{cwd-x}}` 都会被拒绝）。原因是运行时的插值器
> 只认这一种写法，其余写法会抛错并打断**整个请求**。列表里的名字必须同时是当前会话装配里
> **真实注册过**的变量（本部署的各个预设都通过 `@deepseek-ai/dsh-persona` 注册了 `cwd` 与
> `model`）；某个预设没有注册而你仍引用它，请求同样会失败——不确定就把列表清空。

- **Agent 条目**：每条可编辑标识、名称、描述、两个提示词、运行模式（可多选）、后端
  （spawn / fork）、权限（完全 / 只读）、模型（下拉或手填，可选思考等级）、
  是否默认启用、是否纳管；支持上移/下移/复制/删除/新增。
- **自助管理**：是否允许模型创建/修改条目、可修改范围（仅自建 / 全部）、条目上限。
- **闸门（高级）**：逃生舱开关、按前缀拦截、按精确名拦截、豁免名单、打开总开关时的重挂名单。
  收起在官方的 DisclosureRow 里，平时不占版面。
- 底部有保存/恢复出厂；**校验不通过不会写入**（错误以中文列在顶部）。

整页栅格与 DSH 官方的「模型」设置页一致：720px 栏宽、0.5px 描边圆角卡片、胶囊按钮、
官方 Tag / Switch；模型选择用官方的两级菜单（provider → 模型）。

## 4. 语义说明（重要）

### 4.1 闸门怎么工作

每个 agent 作用域上装三层：

| 层 | 手段 | 作用 |
| --- | --- | --- |
| 隐藏层 | `tools.restrict({ deny })` | 让被拦截的名字从模型的工具清单里**消失**（只作用于继承面）。 |
| 执行层 | `tools.guard(...)` | 执行前拒绝，覆盖自有层重挂的工具；返回中文原因。 |
| 重挂层 | `agent.ctx.inject` + `apply` | 按勾选在 agent 自有层装配工具。 |

- **总开关关闭**：允许集合为空 → 隐藏层清掉继承面、守卫清掉一切残留 → 模型完全无法使用
  子代理与编排工具（包括它"记得"的工具名）。
- **总开关打开**：只有被勾选条目的工具名进入允许集合；其余照旧被拦截。
- **子代理**（`session.header.origin === 'subagent'`）只装前两层，永不装第三层 →
  任何层级的子代理都不能再委派。
- **`gate.enabled = false`**（逃生舱）：三层全部不生效，恢复 DSH 原生行为。

### 4.2 原生工具的三档实装

条目表里的「DSH 原生工具」条目按三档择一，取决于当前会话预设到底装配了什么：

| 档 | 条件 | 行为 |
| --- | --- | --- |
| A 放行 | 该名字已在当前作用域可见（预设已提供，如 `dsh-hy4` 下的 `workflow`） | 从拒绝集移除即可，不重复注册。 |
| B 重挂 | 预设没有提供（如 `code-review` 预设没有 delegation 组） | 由本插件在 agent 层调用对应实现包装配。 |
| C 不可用 | 实现包加载失败 / 缺 `workflowEngine` / 只读白名单交集为空 / provider 未注册 | 该条目本次不可用，日志给出中文原因；不影响其它条目。 |

### 4.3 会话选择存在哪里

会话级选择存放在设置命名空间的 `sessions` 映射（键 = 会话 id）：

- 好处：不需要自定义 Remote / 投影 / HTTP 路由，界面与主机读同一份快照；
- 代价：它是**配置文件里的会话状态**，会按最近使用裁剪（上限 120 条会话）；
- 新会话没有记录时回落到「总开关默认值 + 默认启用条目」。

### 4.4 模型自助管理

开启后模型可用 `agent_create` / `agent_update` / `agent_list`：

- 默认作用域 `own`：模型**只能创建/修改自己创建的条目**，内置与用户条目只读；
- 每次都过同一套校验（标识、长度、提示词变量、只读白名单），失败返回中文原因且不写入；
- 每次创建/修改留一条审计日志（`dsh-ob-agent 审计：…`）；
- **新工具下一轮请求才可见**，`agent_create` 的结果文案会明确告知模型；
- 写入的提示词会成为系统提示与子代理 persona，风险与用户手建等价 —— 因此该能力由
  「总开关 + 「Agent 自助管理」条目勾选」双重授权，可随时关闭。

## 5. 内置条目（8 条）

**插件角色（3 条，日常只勾这里）**

> 其中 `agent_authoring` 的 `kind` 是 native（它的三个工具按原生条目的路子装配），但实现由
> 本插件提供，因此在面板里与两个子代理角色一起常显，不落进下面那个折叠分组。

| 标识 | 类型 | 权限 | 默认勾选 | 说明 |
| --- | --- | --- | --- | --- |
| `code_review` | 子代理（一次性 / `spawn`） | 完全 | 否 | 唯一的审查·审计角色，钉死模型 `opencode-go / hy4-preview`，身份提示词即独立审计员 |
| `general` | 子代理（可继续对话 / `spawn`） | 完全 | 是 | 通用委派，对齐原生 `subagent`；返回持久 id，可用 `send_message` 续话 |
| `agent_authoring` | 原生（本插件实现） | — | 是 | `agent_create` / `agent_update` / `agent_list`，让模型自己建 Agent 条目 |

**DSH 原生工具（5 条，面板里默认折叠成一组）**

| 标识 | 工具名 | 默认勾选 | 说明 |
| --- | --- | --- | --- |
| `agents_control` | `send_message` / `interrupt_agent` | 是 | 续话与中止；勾选了「可继续对话」的子代理时会自动一并放行 |
| `agents_list` | `list_agents` | 是 | 列出当前会话的子代理：**能力清单**（已勾选的子代理工具）+ **实例清单**（可续话实例与状态） |
| `workflow` | `workflow` | 否 | 脚本化扇出编排 |
| `ralph` | `ralph` | 否 | 无人值守多轮自迭代 |
| `subagent_native` | `subagent_hy4` 等 | 否 | 放行会话预设里已装配的具名委派工具（不重挂） |

这 5 条**一条都没有删**：它们照旧受闸门管辖（总开关关闭时同样被拦），只是不在面板里展开，
界面平时只多一行。若想让某个原生工具彻底脱离插件、恢复 DSH 原样暴露，把该条目的
「纳入插件管理」关掉即可（一键可逆）。

「恢复出厂」（设置页底栏，**两步确认**）= 把全部可编辑字段写回上面两张表的出厂值，
是删错条目后拿回内置条目的唯一自助入口（迁移规则不会补回被删掉的内置条目）。
它**不动 `sessions`**：各会话已勾选项保留，指向已不存在条目的标识会自动被过滤。
旁边的「放弃修改」只丢弃当前草稿，不写盘。

> **出厂默认带版本号**（`defaultsRevision`）。旧版迁移会把内置条目更新到出厂值、清理已下线
> 条目（`code_audit`、`fork`）、重定向会话勾选；**用户/模型自建条目不变**。从第 2 版升级
> 到第 3 版则只更新内置 `code_review` 的描述和两段提示词，保留它的模型、默认勾选、纳管状态等
> 其它配置，也保留其它内置条目。手动改过审查提示词的用户请先备份：本次迁移会覆盖这两个字段。

## 6. 内置「代码审查」条目的行为

沿用原「代码审计（Hy4）」的模型 `opencode-go / hy4-preview`、一次性模式和完全权限，
但**调用时机和审查标准改为成本优先**：

1. 用户明确要求审查时调用；否则仅在一批实质性代码/配置改动完成、主模型做过针对性自检、
   且独立审查有额外价值时，在汇报前**最多调用一次** `subagent_code_review`。
2. 审查返回后先独立核实：有证据的重要风险再修；误报或收益低于改动成本的建议可说明理由不采纳。
   不要把子代理的每条建议都当成命令。
3. 因建议修改提示文案、注释、格式、测试断言或做了无行为变化的小修，不再复审；仅当修复引入
   测试无法覆盖的安全、数据或兼容性高风险行为变化时，可对**新风险**补充一次聚焦复审。
   纯文档/说明文字改动也无需调用。
4. 审查员只看变更和必要上下文，不做无关全仓扫描或重复测试；只报告值得修复的具体风险，
   给出位置/证据、触发条件、影响、最小修复方向和严重级别；不为凑数提出风格或措辞建议。
   疑点需标明待验证，无值得修复的问题可直接说明。

> **依赖提示**：这一条沿用原「代码审计（Hy4）」的模型路由 `opencode-go / hy4-preview`。
> 若你的 `~/.dsh/settings.yaml` 里没有配 `opencode-go` 这条路由，勾选后 `subagent_code_review`
> 会在启动时失败——届时在设置页把该条目的「模型」清空（继承主会话）或改成你已配置的路由即可。

> 想让它回到「读 `review/GUIDE.md`、按声明的范围跑编译/接口/浏览器测试、产出
> `review/reports/REVIEW-*.md` 报告、更新 `.last-review.json`」的重型流程版，把设置页里
> 的身份提示词换成 `~/.dsh/.agent-presets/code-review/agent.cordis.yml` 里的 persona 即可
> （该文件同时备份在 `plugins/dsh-review-presets`）。

## 7. 验收清单（安装后逐条核对）

1. 设置页出现「子代理」，8 条内置条目可编辑（3 条插件角色 + 5 条 DSH 原生工具）；
   若你的设置段来自旧版本，启动日志里应有一行「出厂默认已迁移到第 3 版」。
2. 新会话默认**关闭**总开关；关闭时模型工具清单里**没有** `subagent*` / `send_message` /
   `interrupt_agent` / `list_agents` / `workflow` / `ralph` / `agent_*`；硬让它调用会收到
   中文拒绝。
3. 打开总开关 → 复选框按「默认启用」勾选；用请求提示检查器确认系统提示里出现
   「本会话已启用以下 Agent 能力」一段，且内容与勾选一致。
4. 勾选「代码审查」→ 出现 `subagent_code_review`；让模型完成一批有审查价值的实质代码改动，
   观察其在自检后至多审查一次；仅按审查建议改提示文案时不应二次调用。
5. 取消勾选 → 该段与工具消失，其它已勾选项不受影响。
6. 同一条助手回复里并行发起两个不同子代理调用 → 均成功。
7. 勾选 `general`（可继续对话）→ 返回持久 id，`send_message` 可续话（续话工具自动放行）。
8. 权限切「只读」→ 子代理没有 `pwsh` / `bash` 等命令工具。
9. 模型自助：让主模型 `agent_create` 建一个条目 → 返回工具名与「下一轮可用」；下一轮能
   调用；设置页出现「模型自建」条目；日志有审计行。
10. `agent_update` 改内置条目被拒；`agent_list` 能列出未勾选条目。
11. 在 `code-review` 会话预设下打开总开关，展开面板里的「DSH 原生工具」分组并勾选
    `workflow` → 档 B 重挂成功可用（若该预设未装配工作流引擎，则显示为不可用并有中文日志）。
12. 面板里「DSH 原生工具」分组默认是**折叠**的：平时只占一行，点开才出现 5 个复选框。
13. 刷新页面 / 换会话 → 各会话选择互不影响；把设置页的「启用闸门」关掉 → 立即恢复
    DSH 原生行为。

## 8. 排障

| 现象 | 排查 |
| --- | --- |
| 聊天框看不到「子代理」面板 | 客户端 bundle 未加载：重启 DSH 后 Ctrl+F5；查看控制台是否有 `[dsh-ob-agent]` 报错。 |
| 聊天框看不到面板、设置页显示「设置命名空间不可用」 | 设置命名空间 `ob-agent` 未注册：确认插件在 `dsh.profile.bundles` 里且 DSH 已重启。 |
| 勾选后工具仍不出现 | 看 DSH 日志里的 `dsh-ob-agent:` 中文告警（实现包加载失败 / 缺 workflowEngine / 只读交集为空 / provider 未注册）。 |
| 模型说工具被拒绝 | 总开关或条目未勾选（守卫的中文拒绝信息会说明）。 |
| `workflow` 显示不可用 | 该会话预设没有装配 `@deepseek-ai/dsh-workflow-worker-thread`（缺 `workflowEngine` 服务）。 |
| 想临时回到原生行为 | 设置页 → 闸门 → 关闭「启用闸门」。 |

## 9. 已知限制

- 会话选择存在设置文件的 `sessions` 映射里（按最近使用裁剪到 120 条），删除会话不会自动
  清理对应记录。
- 隐藏层依赖 `tools.schemas()` 枚举名字；若部署使用 PTC（`run_code`）呈现模式，枚举可能
  只看到传输工具，此时仍会拦截配置里点名的精确名字，但按前缀的枚举覆盖会变弱（守卫始终
  生效）。
- 只读权限通过工具白名单实现；白名单与真实可见工具的交集为空时条目停用（不降级）。
- 预设切到中途新出现的同名原生工具，若本插件已重挂过它，仍以本插件的实例为准
  （两者来自同一实现包，行为等价）。
- 模型自助管理只能受限于设置里的上限与作用域，不能限制它写什么提示词内容 —— 审计日志与
  「模型自建」标记是主要的事后控制手段。
- 客户端 bundle 在顶层 `require` DSH 的 UI 组件库（`@deepseek-ai/dsh-client-ui-primitives`）。
  当前版本确认由 shell 提供该共享模块，因此没有做降级保护；若将来某个 DSH 版本/裁剪版不再
  提供它，面板与设置页会一起加载失败。届时把两个组件的 import 改成惰性探测即可（普通
  `require` 之外没有运行期保护，`package.json` 里的 `optional` 只在安装期生效）。
